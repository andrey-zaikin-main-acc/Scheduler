# Спецификация интерфейса MVP

## Общие требования

- Приложение запускается локально через Streamlit.
- Авторизация не нужна.
- Данные сохраняются в SQLite.
- Схема базы создаётся автоматически при запуске приложения; пересчёт запускается только кнопкой «Пересчитать план» в боковой панели.
- Вверху боковой панели показаны состояние плана, последний пересчёт и число конфликтов. Ниже находятся кнопка пересчёта, навигация, «Назад»/«Вперёд» и раскрывающийся блок переноса базы данных.
- Блок «База данных» выгружает актуальный сохранённый снимок (после ввода автора), загружает проверенный снимок с резервным копированием текущей базы и позволяет отменить последнюю загрузку. Несохранённые экранные правки перед загрузкой или откатом блокируют операцию.
- Текущая навигация содержит разделы «Реестр заказов», «Маршруты», «Участки», «Производственный план», «Свободные слоты», «Диаграмма Ганта», «Конфликты» и «Результаты пересчёта».

## Реестр заказов

Основные колонки:

- ID / номер заказа;
- клиент;
- продукция;
- тираж;
- приоритет;
- режим планирования;
- заданные дата запуска и дата отгрузки;
- расчётные дата запуска и дата отгрузки;
- маршрут;
- статус;
- признаки планирования и конфликта;
- группа и признак связанных заказов.

Действия:

- открыть форму нового заказа кнопкой «Новый заказ»;
- редактировать заказ прямо в таблице;
- применить все изменения кнопкой «Пересчитать план»;
- удалить выбранные строки из черновика кнопкой «Удалить выбранные заказы»;
- изменить статус;
- отменить или повторить экранное действие кнопками «Назад»/«Вперёд».

Блок предварительной проверки маршрута открывается кнопкой «📐 Проверка тиража и слотов». Пользователь выбирает период, активный маршрут и желаемый тираж. При открытии реестра расчёт мощности не запускается автоматически: до нажатия кнопки «Рассчитать доступный тираж» отображаются только выбранные параметры и кнопки действий. После расчёта система показывает максимальный реально размещаемый тираж, ограничивающий участок, предупреждения и детализацию по операциям. При изменении периода или маршрута старый расчёт скрывается, а свободные слоты очищаются; при изменении желаемого тиража очищаются ранее найденные слоты. Поиск свободных дат отгрузки доступен только после актуального расчёта мощности, а желаемый тираж должен быть больше 0. Проверка не создаёт заказ и не меняет сохранённый производственный план.

Клиент и продукция в MVP — текстовые поля.

## Редактирование заказа

Заказы редактируются прямо в таблице реестра. Поля:

- номер заказа;
- клиент;
- продукция;
- тираж;
- положительный уникальный приоритет;
- режим планирования;
- заданная дата запуска и заданная дата отгрузки;
- маршрут;
- статус.

Валидация:

- номер заказа заполнен и уникален;
- клиент заполнен;
- продукция заполнена;
- тираж больше 0;
- приоритет является положительным целым числом и не повторяется среди неотменённых заказов;
- выбран поддерживаемый режим и заполнена его активная заданная дата;
- активный маршрут выбран;
- вручную можно выбрать только «Новый», «Отменён» или оставить сохранённое пустое системное состояние.

## Справочник участков

Поля:

- название;
- доступное время в месяц;
- активность;
- «Нельзя прерывать заказ при планировании» — checkbox, по умолчанию выключен для новой строки.

Валидация:

- название участка заполнено и уникально;
- доступное время в месяц должно быть больше 0;
- активность задана булевым значением;
- запрет прерывания заказа задан булевым значением.

## Справочник маршрутов

Поля маршрута:

- название;
- описание;
- активность.

Поля операции маршрута:

- порядковый номер;
- участок;
- трудоёмкость на 1000 шт.;
- минимальная передаточная партия к следующей операции.

Валидация:

- название маршрута заполнено и уникально;
- маршрут должен иметь хотя бы одну операцию для планирования заказов;
- номер операции должен быть больше 0 и уникален внутри маршрута;
- участок операции выбран;
- трудоёмкость операции должна быть больше 0;
- минимальная передаточная партия не должна быть отрицательной; значение 0 сохраняется как отсутствие ограничения.

## Производственный план

Раздел «Производственный план» доступен в боковом меню Streamlit и показывает плановые операции и дневные размещения.

Фильтры:

- период;
- участок;
- заказ;
- статус.

## Диаграмма Ганта

Режимы:

1. По заказам — строки соответствуют заказам, полосы соответствуют операциям.
2. По участкам — строки соответствуют участкам, полосы соответствуют заказам/операциям.

В подсказке операции показываются:

- заказ;
- участок;
- операция маршрута;
- дата и время начала;
- дата и время окончания;
- плановые часы.

## Свободные слоты

Раздел «Свободные слоты» доступен в боковом меню Streamlit. Период выбирает пользователь. По умолчанию — ближайшие 30 дней.

Показывается:

- участок;
- дата;
- доступные часы на дату, рассчитанные из месячной мощности;
- занятые часы;
- свободные часы.

Отдельно показывается теоретический максимальный тираж по маршрутам. Этот расчёт основан только на суммарной свободной мощности участков и не учитывает последовательность операций, минимальные партии и срок отгрузки; реально размещаемый тираж проверяется в реестре заказов.

## Конфликты

Показывается:

- заказ;
- срок отгрузки;
- ограничивающий участок;
- требуемые часы;
- свободные часы;
- дефицит;
- мешающие заказы;
- причина.

## Результаты пересчёта

Показывается последний пересчёт:

- дата и время запуска;
- статус;
- краткая сводка;
- список изменений.

Полное версионирование плана в MVP не требуется.

## Черновики сессии

Таблицы заказов, маршрутов/операций и участков редактируются как `session_state`-черновики. Форма `Новый заказ` добавляет временную строку. `Удалить выбранные заказы` удаляет несколько строк с экрана и накапливает ID для будущей транзакции. Глобальная команда называется `Пересчитать план`, команды справочников — `Сохранить изменения` и не запускают пересчёт. Ошибка не сбрасывает редактор; успешный результат показывается flash-сообщением после rerun.

Реестр раздельно показывает заданные и расчётные даты, ручной статус, а также read-only флаги `Запланирован` и `Конфликт планирования`. Поле времени начала рабочего дня больше не редактируется.

## Модель экранного сохранения (актуальная)

Все правки сначала являются экранным черновиком. Локальное сохранение справочника не пересчитывает план; глобальная команда проверяет все разделы и pending delete до единой транзакции. Ошибка заполнения сохраняет черновик и историю, конфликт планирования является успешным системным результатом.

До записи черновиков глобальная команда проверяет активную заданную дату режима. Новые и ранее конфликтные заказы не могут рассчитываться от заданной даты, которая раньше текущей даты. Для ранее запланированных заказов прошедшие даты допустимы, поскольку заказ может уже находиться в производстве. Ручной возврат ранее запланированного заказа в статус «Новый» снова включает проверку текущей даты. Отменённые заказы эту проверку не проходят; при ошибке экранный черновик, pending delete и история «Назад»/«Вперёд» сохраняются.

Полный проход использует неизменяемый snapshot трёх очередей: ранее запланированные, новые, ранее конфликтные. Приоритет — глобально уникальное положительное целое; связанные строки одной группы занимают непрерывный блок. Оба заданных поля даты разрешены в черновике, а неиспользуемое поле очищается только после успешного расчёта. Системный результат читается из planned operations либо planning conflicts.

Таблицы блокируют только фиксированные системные столбцы; в заказах это ID, группа, две расчётные даты и два флага результата. «Связанные заказы» редактируется. История undo/redo, отдельные черновики операций по route ID и навигационное подтверждение живут в сессии. Свободные слоты обязаны использовать неперсистентную симуляцию основного PlanningEngine. Статические ресурсы табличного адаптера должны включаться в Windows EXE и не зависеть от CDN.

## Экранные черновики и навигация

Все четыре редактируемые таблицы (заказы, маршруты, операции и участки) проходят через единый адаптер событий. Сохранённая строка адресуется положительным ID базы, временная — отрицательным `_draft_id`. Служебный checkbox выбора не создаёт бизнес-действие истории. История «Назад»/«Вперёд» общая для сессии и применяется к черновику, не к базе данных. Локальное сохранение маршрутов/операций и участков не запускает планировщик; глобальное действие сохраняет черновики и выполняет один пересчёт.

При уходе с изменённого справочника текущая страница остаётся видимой до решения «Сохранить изменения?». Заказы такого подтверждения не требуют и остаются в сессионном черновике.

## Единый черновик заказов

Все колонки реестра редактируются в одном сессионном снимке, кроме ID, системной группы, расчётных дат и системных флагов. Ручной статус допускает только пустое системное состояние, «Новый» и «Отменён». Добавление и массовое удаление являются атомарными действиями undo/redo и не обращаются к SQLite. Сброс widget state выполняется при загрузке БД, успешном пересчёте, discard, undo/redo и программном изменении набора строк, но не при вводе ячейки.
