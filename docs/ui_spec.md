# Спецификация интерфейса MVP

## Общие требования

- Приложение запускается локально через Streamlit.
- Авторизация не нужна.
- Данные сохраняются в SQLite.
- Пересчёт запускается автоматически после фактического сохранения изменений в справочниках/заказах и вручную кнопкой «Пересчитать план» в боковой панели.
- В боковой панели есть группа «База данных» со служебными действиями «Создать таблицы» и «Загрузить актуальные данные», а также группа «Планирование» с действием «Пересчитать план».
- Текущая навигация содержит разделы «Реестр заказов», «Маршруты», «Участки», «Производственный план», «Свободные слоты», «Диаграмма Ганта», «Конфликты» и «Результаты пересчёта».

## Реестр заказов

Колонки:

- ID / номер заказа;
- клиент;
- продукция;
- тираж;
- срок отгрузки;
- маршрут;
- статус;
- рассчитанная дата запуска;
- признак конфликта.

Действия:

- добавить черновую строку кнопкой «Добавить заказ»;
- редактировать заказ прямо в таблице;
- применить изменения кнопкой «Сохранить изменения»;
- удалить выбранный заказ кнопкой «Удалить заказ»;
- изменить статус;
- пересчитать план автоматически после сохранения/удаления или вручную из боковой панели.

Перед таблицей заказов расположен блок предварительной проверки маршрута. Пользователь выбирает период, активный маршрут и желаемый тираж. Период по умолчанию — текущий календарный месяц. При открытии реестра расчёт мощности не запускается автоматически: до нажатия кнопки «Рассчитать доступный тираж» отображаются только выбранные параметры и кнопки действий. После расчёта система показывает максимальный реально размещаемый тираж, ограничивающий участок, предупреждения и детализацию по операциям. При изменении периода или маршрута старый расчёт скрывается, а свободные слоты очищаются; при изменении желаемого тиража очищаются ранее найденные слоты. Поиск свободных дат отгрузки доступен только после актуального расчёта мощности, а желаемый тираж должен быть больше 0. Проверка не создаёт заказ и не меняет сохранённый производственный план.

Клиент и продукция в MVP — текстовые поля.

## Редактирование заказа

Заказы редактируются прямо в таблице реестра. Поля:

- номер заказа;
- клиент;
- продукция;
- тираж;
- срок отгрузки;
- маршрут;
- статус.

Валидация:

- номер заказа заполнен и уникален;
- клиент заполнен;
- продукция заполнена;
- тираж больше 0;
- срок отгрузки заполнен;
- активный маршрут выбран;
- статус выбран из поддерживаемого списка.

## Справочник участков

Поля:

- название;
- доступное время в месяц;
- время начала рабочего дня в формате `HH:MM`;
- активность.

Валидация:

- название участка заполнено и уникально;
- доступное время в месяц должно быть больше 0;
- время начала рабочего дня должно быть в формате `HH:MM`;
- активность задана булевым значением.

## Справочник маршрутов

Поля маршрута:

- название;
- описание;
- активность.

Поля операции маршрута:

- порядковый номер;
- участок;
- трудоёмкость на 1000 шт.;
- минимальная передаточная партия к следующей операции.

Валидация:

- название маршрута заполнено и уникально;
- маршрут должен иметь хотя бы одну операцию для планирования заказов;
- номер операции должен быть больше 0 и уникален внутри маршрута;
- участок операции выбран;
- трудоёмкость операции должна быть больше 0;
- минимальная передаточная партия не должна быть отрицательной; значение 0 сохраняется как отсутствие ограничения.

## Производственный план

Раздел «Производственный план» доступен в боковом меню Streamlit и показывает плановые операции и дневные размещения.

Фильтры:

- период;
- участок;
- заказ;
- статус.

## Диаграмма Ганта

Режимы:

1. По заказам — строки соответствуют заказам, полосы соответствуют операциям.
2. По участкам — строки соответствуют участкам, полосы соответствуют заказам/операциям.

В подсказке операции показываются:

- заказ;
- участок;
- операция маршрута;
- дата и время начала;
- дата и время окончания;
- плановые часы.

## Свободные слоты

Раздел «Свободные слоты» доступен в боковом меню Streamlit. Период выбирает пользователь. По умолчанию — ближайшие 30 дней.

Показывается:

- участок;
- дата;
- доступные часы на дату, рассчитанные из месячной мощности;
- занятые часы;
- свободные часы.

Отдельно показывается теоретический максимальный тираж по маршрутам. Этот расчёт основан только на суммарной свободной мощности участков и не учитывает последовательность операций, минимальные партии и срок отгрузки; реально размещаемый тираж проверяется в реестре заказов.

## Конфликты

Показывается:

- заказ;
- срок отгрузки;
- ограничивающий участок;
- требуемые часы;
- свободные часы;
- дефицит;
- мешающие заказы;
- причина.

## Результаты пересчёта

Показывается последний пересчёт:

- дата и время запуска;
- статус;
- краткая сводка;
- список изменений.

Полное версионирование плана в MVP не требуется.
