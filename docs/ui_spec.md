# Спецификация интерфейса MVP

## Общие требования

- Приложение запускается локально.
- Авторизация не нужна.
- Данные сохраняются в SQLite.
- Пересчёт запускается автоматически после сохранения изменений в редактируемых таблицах и вручную кнопкой «Пересчитать план» в боковой панели.
- В боковой панели есть служебные действия «Создать таблицы» и «Загрузить актуальные данные».

## Реестр заказов

Колонки:

- ID / номер заказа;
- клиент;
- продукция;
- тираж;
- срок отгрузки;
- маршрут;
- статус;
- рассчитанная дата запуска;
- признак конфликта.

Действия:

- добавить заказ;
- редактировать заказ прямо в таблице;
- удалить выбранный заказ;
- изменить статус;
- пересчитать план автоматически после сохранения или вручную из боковой панели.

Перед таблицей заказов расположен блок предварительной проверки маршрута. Пользователь выбирает период, активный маршрут и желаемый тираж. Система показывает максимальный доступный тираж, ограничивающий участок, детализацию по операциям и список возможных дат отгрузки для указанного тиража. Проверка не создаёт заказ и не меняет сохранённый производственный план.

Клиент и продукция в MVP — текстовые поля.

## Редактирование заказа

Заказы редактируются прямо в таблице реестра. Поля:

- номер заказа;
- клиент;
- продукция;
- тираж;
- срок отгрузки;
- маршрут;
- статус.

Валидация:

- номер заказа заполнен и уникален;
- клиент заполнен;
- продукция заполнена;
- тираж больше 0;
- срок отгрузки заполнен;
- активный маршрут выбран;
- статус выбран из поддерживаемого списка.

## Справочник участков

Поля:

- название;
- доступные часы в день;
- активность.

Валидация:

- название участка заполнено и уникально;
- доступные часы должны быть больше 0;
- активность задана булевым значением.

## Справочник маршрутов

Поля маршрута:

- название;
- описание;
- активность.

Поля операции маршрута:

- порядковый номер;
- участок;
- трудоёмкость на 1000 шт.;
- минимальная передаточная партия к следующей операции.

Валидация:

- название маршрута заполнено и уникально;
- маршрут должен иметь хотя бы одну операцию для планирования заказов;
- номер операции должен быть больше 0 и уникален внутри маршрута;
- участок операции выбран;
- трудоёмкость операции должна быть больше 0;
- минимальная передаточная партия не должна быть отрицательной; значение 0 сохраняется как отсутствие ограничения.

## Производственный план

Код содержит страницу производственного плана, однако текущая навигация Streamlit не выводит этот раздел в боковом меню. Страница показывает плановые операции и дневные размещения.

Фильтры:

- период;
- участок;
- заказ;
- статус.

## Диаграмма Ганта

Режимы:

1. По заказам — строки соответствуют заказам, полосы соответствуют операциям.
2. По участкам — строки соответствуют участкам, полосы соответствуют заказам/операциям.

В подсказке операции показываются:

- заказ;
- участок;
- операция маршрута;
- дата и время начала;
- дата и время окончания;
- плановые часы.

## Свободные слоты

Код содержит страницу и сервис расчёта свободных слотов, однако текущая навигация Streamlit не выводит этот раздел в боковом меню. Период выбирает пользователь. По умолчанию — ближайшие 30 дней.

Показывается:

- участок;
- дата;
- доступные часы;
- занятые часы;
- свободные часы.

Отдельно показывается примерный возможный тираж по маршрутам.

## Конфликты

Показывается:

- заказ;
- срок отгрузки;
- ограничивающий участок;
- требуемые часы;
- свободные часы;
- дефицит;
- мешающие заказы;
- причина.

## Результаты пересчёта

Показывается последний пересчёт:

- дата и время запуска;
- статус;
- краткая сводка;
- список изменений.

Полное версионирование плана в MVP не требуется.
