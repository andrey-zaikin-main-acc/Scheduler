# DrawPPT / Production Planner MVP

Локальный однопользовательский MVP приложения планирования производства с хранением данных в SQLite.

## Цель

Прототип проверяет ключевую расчётную логику:

- расчёт потребности по трудоёмкости на 1000 шт.;
- обратное планирование от срока отгрузки;
- учёт маршрутов и производственных участков с месячной доступной мощностью;
- частичную передачу партии между операциями;
- пересчёт всего плана при изменениях;
- выявление конфликтов;
- свободные слоты и предварительную проверку доступного тиража по маршруту;
- поиск возможных дат отгрузки без создания заказа;
- диаграмму Ганта по заказам и по участкам.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.db.init_db
python -m app.db.seed_data
streamlit run app/main.py
```

После запуска приложение открывается как локальный Streamlit-интерфейс. В боковой панели доступны служебные действия:

- «Создать таблицы» — создаёт схему SQLite, если она ещё не создана;
- «Загрузить актуальные данные» — идемпотентно загружает seed-данные;
- «Пересчитать план» — очищает сохранённый план/конфликты и строит план заново по текущим заказам и справочникам.

## Локальная база данных

По умолчанию SQLite-файл создаётся в `data/planner.sqlite3`. Каталог `data/` создаётся автоматически при инициализации базы.

Полезные команды:

```bash
# создать таблицы без изменения существующих данных
python -m app.db.init_db

# загрузить или обновить seed-данные, не удаляя базу
python -m app.db.seed_data

# пересоздать локальную базу и загрузить seed-данные заново
python -m app.db.seed_data --reset
```

`--reset` удаляет текущий SQLite-файл, поэтому команда подходит для локальной разработки и демонстрационных стендов, но не для сохранения ручных данных.

## Актуальные seed-данные

Seed-данные загружаются из `app/db/seed_data.py` и соответствуют исходному Excel-файлу: реальные производственные участки, 8 технологических потоков и минимальный набор заказов на этих маршрутах.

Загрузка seed-данных идемпотентна: повторный запуск обновляет справочники и тестовые заказы по их ключевым полям, а не создаёт дубликаты.

## Работа с заказами

Заказы редактируются прямо в таблице реестра, но изменения применяются только после нажатия «Сохранить изменения». Добавление новой строки и удаление выбранного заказа выполняются отдельными кнопками. После сохранения изменений, создания/удаления заказа или изменения справочников приложение запускает пересчёт плана. Дата запуска и признак конфликта являются расчётными полями и вручную не редактируются.

В реестре заказов доступен предварительный блок «Проверка доступного тиража и слотов отгрузки». При открытии реестра расчёт мощности не выполняется автоматически: пользователь выбирает период, маршрут и желаемый тираж, затем запускает проверку отдельной кнопкой «Рассчитать доступный тираж». После расчёта блок показывает максимальный доступный тираж, ограничивающий участок, предупреждения и детализацию операций. Свободные слоты отгрузки можно искать только после актуального расчёта мощности для выбранных периода и маршрута; желаемый тираж должен быть больше нуля. Предварительная проверка не создаёт заказ и не изменяет сохранённый производственный план.

## Разделы интерфейса

Текущая навигация Streamlit содержит разделы:

- «Реестр заказов»;
- «Маршруты»;
- «Участки»;
- «Производственный план»;
- «Свободные слоты»;
- «Диаграмма Ганта»;
- «Конфликты»;
- «Результаты пересчёта».

Раздел «Производственный план» показывает плановые операции и дневные размещения с фильтрами по периоду, участку, заказу и статусу заказа. Раздел «Свободные слоты» показывает свободные часы по участкам и теоретический максимальный тираж по маршрутам за выбранный период; этот показатель не учитывает последовательность операций, минимальные партии и срок отгрузки, поэтому реально размещаемый тираж проверяется в реестре заказов.

## Desktop-версия Windows

Desktop-сборка сохраняет существующий Streamlit-интерфейс, но запускает его внутри нативного окна Windows через `pywebview`. Пользователю готовой сборки не нужно устанавливать Python, зависимости или запускать команды вручную: приложение стартует двойным кликом по `DrawPPT.exe`.

### Требования для desktop-окна

На Windows должен быть установлен Microsoft Edge WebView2 Runtime. Обычно он уже присутствует в современных версиях Windows и Microsoft Edge; если окно не открывается, установите WebView2 Runtime с сайта Microsoft.

### Сборка

В PowerShell из корня репозитория выполните:

```powershell
.\scripts\build_windows.ps1
```

Скрипт создаёт или переиспользует `.venv`, устанавливает runtime-зависимости из `requirements.txt` и build-зависимости из `requirements-build.txt`, очищает `build/` и `dist/`, затем запускает PyInstaller по `DrawPPT.spec`.

Итоговый исполняемый файл создаётся здесь:

```text
dist/DrawPPT/DrawPPT.exe
```

Основной формат поставки — `onedir`: передавайте пользователю весь каталог `dist/DrawPPT/`, а не только exe-файл.

### Запуск готового приложения

1. Откройте каталог `dist/DrawPPT/`.
2. Запустите `DrawPPT.exe` двойным кликом.
3. Дождитесь открытия отдельного окна `DrawPPT`.
4. Работайте с теми же разделами Streamlit-интерфейса, что и в dev-режиме.
5. Закройте окно приложения — встроенный локальный Streamlit-сервер будет остановлен вместе с приложением.

Desktop launcher запускает локальный Streamlit-сервер только на `127.0.0.1`, выбирает свободный порт автоматически, работает в headless-режиме и не открывает внешний браузер.

### База данных desktop-версии

В dev-режиме SQLite по-прежнему хранится в:

```text
data/planner.sqlite3
```

В собранном Windows-приложении пользовательская база хранится отдельно от дистрибутива:

```text
%LOCALAPPDATA%\DrawPPT\planner.sqlite3
```

При первом запуске desktop-приложение создаёт каталог данных, создаёт таблицы и загружает текущие seed-данные только если файла базы ещё не было. При последующих запусках существующая база не удаляется, пользовательские данные не перезаписываются, а seed-данные автоматически не запускаются. Кнопки управления БД в боковой панели Streamlit сохранены.

## Session drafts and atomic planning

Editable registries now use session-scoped screen drafts. Adding or pre-deleting a row does not touch SQLite. The global save action validates all participating rows, applies the draft and rebuilds the plan in one transaction; validation and technical errors preserve the draft. Route/work-center saves are explicit section actions. Manual order status is limited to **Новый** and **Отменён**; planning outcome is displayed independently.

## Экранные черновики и полный пересчёт

Редактируемые таблицы хранят значения только в `st.session_state` до явного действия. Участки и маршруты сохраняются локально кнопкой «Сохранить изменения» без пересчёта. «Пересчитать план» валидирует все черновики и pending delete до записи, затем сохраняет их, выполняет один полный пересчёт и один commit.

Очередь фиксируется до планирования: ранее запланированные, новые, ранее конфликтные; внутри очереди действует введённый положительный уникальный приоритет. Связанные дети образуют блок по минимальному приоритету и `child_sequence_number`. После прохода приоритеты становятся общей последовательностью; отменённые получают пустое отображение (в SQLite используется недопустимый для ввода sentinel 0). План и конфликт — взаимоисключающие системные результаты, ручной статус допускает «Новый», «Отменён» или сохранённое пустое значение.

История «Назад/Вперёд» относится только к экранным действиям текущей сессии. Удаление заказов откладывается до успешной общей транзакции. Табличный Python-адаптер использует стабильные DB/temporary row keys и передаёт структурированные события визуального фокуса/анимации без frontend-бизнес-логики.

### Черновики интерфейса

Редактируемые таблицы используют стабильные ключи строк и общую сессионную историю «Назад»/«Вперёд». Справочники сохраняются локально без пересчёта, а кнопка полного пересчёта атомарно применяет все экранные черновики.
